# 애플리케이션 서버 목록

## 개요

애플리케이션 서버 목록 화면은 LibriX에 등록된 모든 Liberty 서버들을 한눈에 볼 수 있는 통합 관리 화면입니다. 여러 호스트에 분산된 서버들을 중앙에서 모니터링하고 관리할 수 있습니다.

## 애플리케이션 서버 목록이란?

Liberty 서버들의 종합 목록으로, 각 서버의 상태, 리소스 사용량, 배포된 애플리케이션 등을 실시간으로 확인할 수 있는 화면입니다.

## Liberty의 전통적인 서버 관리

### 명령줄 도구

**각 서버 개별 확인:**
```bash
# Server1 상태 확인
ssh host1 "cd /opt/liberty && bin/server status myServer"

# Server2 상태 확인
ssh host2 "cd /opt/liberty && bin/server status myServer"

# Server3 상태 확인
ssh host3 "cd /opt/liberty && bin/server status myServer"
```

**문제점:**
- 서버별 개별 명령 실행
- 전체 현황 파악 어려움
- 자동화 스크립트 필요
- 실시간 모니터링 불가

### WebSphere Liberty Admin Center

**제한된 기능:**
- 단일 서버만 관리
- 다중 서버 통합 뷰 없음
- 기본적인 시작/중지만 가능

### LibriX의 통합 관리 방식

**중앙 집중 뷰:**
- 모든 서버를 한 화면에 표시
- 실시간 상태 업데이트
- 대시보드 형태의 시각화

**일괄 작업:**
- 여러 서버 동시 선택
- 그룹 단위 작업 수행
- 클러스터 단위 관리

**고급 필터링:**
- 상태별, 호스트별, 클러스터별 필터
- 검색 및 정렬
- 사용자 정의 뷰

## 애플리케이션 서버 목록 화면

화면 접근 경로:

```
서버 → 애플리케이션 서버
```

### 목록 표시 정보

**기본 정보:**
- **서버 이름**: Liberty 서버 식별자
- **호스트**: 서버가 실행 중인 호스트 이름
- **상태**: 실행 중/중지/알 수 없음
- **버전**: Liberty 버전
- **시작 시간**: 서버 시작 시각
- **가동 시간**: 연속 실행 시간

**리소스 사용량:**
- **CPU**: CPU 사용률 (%)
- **메모리**: 힙 메모리 사용량 (MB/GB)
- **스레드**: 활성 스레드 수
- **요청**: 초당 요청 수 (TPS)

**배포 정보:**
- **애플리케이션 수**: 배포된 애플리케이션 개수
- **클러스터**: 속한 클러스터 (있는 경우)
- **세션 도메인**: 속한 세션 도메인 (있는 경우)

### 상태 표시

**상태 아이콘:**
- 🟢 **실행 중**: 정상 작동
- 🟡 **경고**: 성능 저하 또는 일부 문제
- 🔴 **중지**: 서버 미실행
- ⚪ **알 수 없음**: 통신 불가

**상태별 자동 색상:**
```
CPU > 80%: 🟡 경고
메모리 > 90%: 🟡 경고
응답 없음: ⚪ 알 수 없음
```

## 필터 및 검색

### 필터 옵션

**상태별 필터:**
```
☑ 실행 중
☐ 중지
☐ 경고
☐ 알 수 없음
```

**호스트별 필터:**
```
드롭다운에서 호스트 선택
→ 해당 호스트의 서버만 표시
```

**클러스터별 필터:**
```
☑ web-app-cluster
☐ api-cluster
☐ 클러스터 미소속
```

### 검색 기능

**서버 이름으로 검색:**
```
검색어: "prod"
결과: prod-server1, prod-server2, prod-server3
```

**호스트 이름으로 검색:**
```
검색어: "web01"
결과: web01.company.com의 모든 서버
```

### 정렬

**정렬 기준:**
- 서버 이름 (A-Z, Z-A)
- 호스트 이름
- 상태
- CPU 사용률 (높음→낮음, 낮음→높음)
- 메모리 사용량
- 시작 시간

**사용 예:**
```
CPU 사용률 높음 → 낮음 정렬
→ 부하가 높은 서버 우선 표시
```

## 대량 작업

### 여러 서버 선택

**선택 방법:**
- 체크박스로 개별 선택
- Shift + 클릭으로 범위 선택
- "모두 선택" 버튼

**선택 상태:**
```
3개 서버 선택됨:
- server1
- server2
- server3
```

### 일괄 시작/중지

**일괄 시작:**
```
1. 중지된 서버들 선택
2. "시작" 버튼 클릭
3. 진행 상황 표시
   - server1: 시작 중...
   - server2: 시작 완료
   - server3: 시작 중...
```

**일괄 중지:**
```
옵션 선택:
○ 정상 중지 (현재 요청 완료 후)
○ 즉시 중지 (강제)
```

### 일괄 재시작

**롤링 재시작:**
```
1. 서버들 선택
2. "재시작" → "롤링 재시작" 선택
3. 순차적 재시작 수행
   - server1 재시작 → 완료 → server2 → 완료 → server3
```

**동시 재시작:**
```
모든 서버 동시 재시작
→ 짧은 서비스 중단 발생
```

## 서버 그룹화

### 뷰 저장

**사용자 정의 뷰:**
```
이름: "운영 서버"
필터:
- 호스트: prod-*
- 상태: 실행 중
- 클러스터: web-app-cluster

저장 → 빠른 접근 메뉴에 추가
```

### 태그 관리

**서버 태그:**
```
server1: #production #web #critical
server2: #production #api
server3: #development #test
```

**태그로 필터링:**
```
#production → 운영 서버만 표시
#critical → 중요 서버만 표시
```

## Liberty vs LibriX 비교

| 항목 | Liberty 명령줄 | Admin Center | LibriX |
|------|--------------|--------------|--------|
| 통합 뷰 | 없음 | 단일 서버만 | 전체 서버 |
| 실시간 모니터링 | 없음 | 제한적 | 완전 지원 |
| 일괄 작업 | 스크립트 필요 | 불가 | GUI 지원 |
| 필터/검색 | 불가 | 제한적 | 고급 기능 |
| 대시보드 | 없음 | 기본 | 고급 |

## 모범 사례

### 서버 명명 규칙

**권장 규칙:**
```
{환경}-{서비스}-{번호}

예:
prod-web-01
prod-web-02
prod-api-01
dev-test-01
```

**혜택:**
- 쉬운 식별
- 자동 그룹화
- 정렬 편의성

### 모니터링 전략

**정기 점검:**
- 매일: 전체 서버 상태 확인
- 주간: 리소스 사용 추이 분석
- 월간: 용량 계획 검토

**알림 설정:**
```
CPU > 80%: 30분 이상 지속 시 알림
메모리 > 90%: 즉시 알림
서버 중지: 즉시 알림
```

### 용량 관리

**서버 증설 기준:**
```
평균 CPU > 70% (1주일)
→ 서버 추가 고려

평균 메모리 > 80% (1주일)
→ 메모리 증설 또는 서버 추가
```

## 문제 해결

### 서버가 목록에 표시되지 않음

**원인:**
1. LibriX Agent 미실행
2. 네트워크 연결 문제
3. 방화벽 차단

**해결:**
```bash
# Agent 상태 확인
systemctl status librix-agent

# 네트워크 확인
telnet librix-server 9443
```

### 상태가 "알 수 없음"으로 표시

**원인:**
1. 서버 응답 없음
2. Agent 통신 실패
3. 일시적 네트워크 문제

**해결:**
1. 서버 로그 확인
2. Agent 재시작
3. 네트워크 점검

### 리소스 사용량이 업데이트되지 않음

**원인:**
1. Agent 오류
2. JMX 연결 문제
3. 캐시 문제

**해결:**
1. 수동 새로고침
2. Agent 재시작
3. 브라우저 캐시 삭제
