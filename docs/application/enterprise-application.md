## 개요

엔터프라이즈 애플리케이션 메뉴는 Liberty 서버에 배포된 모든 웹 애플리케이션(WAR, EAR)을 중앙에서 관리할 수 있는 인터페이스를 제공합니다. 이 메뉴를 통해 애플리케이션의 전체 생명주기를 관리할 수 있습니다.

### Liberty 계열의 애플리케이션 관리 방식

Open Liberty와 WebSphere Liberty에서는 배포된 애플리케이션을 관리하기 위해 주로 다음 방법들을 사용합니다:

**명령줄 도구 (server 명령)**
```bash
# 서버 시작 (모든 애플리케이션 자동 시작)
server start myServer

# 서버 중지 (모든 애플리케이션 중지)
server stop myServer

# 개별 애플리케이션 제어는 불가능
```

**server.xml 수동 편집**
```xml
<!-- 애플리케이션 비활성화 -->
<webApplication id="myapp" 
                location="myapp.war"
                autoStart="false"/>

<!-- 서버 재시작 필요 -->
```

**문제점:**
- 개별 애플리케이션 제어 어려움
- 서버 재시작 필요
- 여러 서버에 배포된 애플리케이션 일괄 관리 불가
- 실시간 상태 모니터링 부재
- GUI 기반 관리 도구 없음 (Admin Center는 제한적)

### LibriX의 애플리케이션 관리 방식

LibriX는 WebSphere Application Server의 ISC(Integrated Solutions Console) 스타일의 애플리케이션 관리 기능을 제공합니다:

**중앙 집중식 관리**
- 모든 서버의 애플리케이션을 한 화면에서 확인
- 클러스터 단위 일괄 작업 지원
- Collective Controller 기능 제공

**실시간 제어**
- 서버 재시작 없이 애플리케이션 시작/중지
- 즉시 적용되는 설정 변경
- 실시간 상태 모니터링

**GUI 기반 인터페이스**
- 직관적인 웹 UI
- 드래그 앤 드롭 지원
- 시각적 상태 표시

## 주요 기능

엔터프라이즈 애플리케이션 메뉴는 다음 기능을 제공합니다:

- **애플리케이션 목록 조회**: 배포된 모든 애플리케이션의 현재 상태 확인
- **시작/중지**: 애플리케이션의 실행 상태 제어
- **설치**: 새로운 애플리케이션 배포
- **중지**: 기존 애플리케이션 제거
- **업데이트**: 배포된 애플리케이션의 새 버전으로 교체
- **내보내기**: 애플리케이션 구성 정보 내보내기

## 애플리케이션 생명주기

LibriX를 통한 애플리케이션 생명주기는 다음과 같습니다:

```
설치 → 시작 → 실행 중 → 중지 → 업데이트/설치제거
           ↓                      ↓
    [새 애플리케이션 설치]    [애플리케이션 제거]
```

## 엔터프라이즈 애플리케이션 메뉴 화면

![엔터프라이즈 애플리케이션 메뉴 화면](images/enterprise_app/enterprise_app_main.png)

엔터프라이즈 애플리케이션 메뉴는 다음 섹션으로 구성됩니다:

### 1. 작업 버튼 영역

화면 상단에는 애플리케이션 관리를 위한 주요 작업 버튼들이 배치됩니다:

- **설치**: 새 애플리케이션을 서버에 배포
- **시작**: 선택한 애플리케이션을 실행
- **설치제거**: 선택한 애플리케이션을 서버에서 제거
- **중지**: 실행 중인 애플리케이션을 정지
- **업데이트**: 새 버전으로 교체
- **내보내기**: 애플리케이션 구성 내보내기

### 2. 애플리케이션 목록 테이블

배포된 애플리케이션의 상세 정보를 테이블 형태로 표시:

| 컬럼명 | 설명 |
|--------|------|
| **선택** | 체크박스로 작업 대상 애플리케이션 선택 |
| **애플리케이션 이름** | 배포 시 지정한 애플리케이션 고유 이름 |
| **유형** | WAR (웹 애플리케이션) 또는 EAR (엔터프라이즈 애플리케이션) |
| **상태** | 실행 중 (녹색), 중지됨 (회색), 오류 (빨강) |
| **대상** | 배포된 서버 또는 클러스터 이름 |
| **Context Root** | 애플리케이션 접근 URL 경로 |
| **시작 시간** | 애플리케이션이 시작된 시각 |

### 3. 필터 및 검색 기능

대량의 애플리케이션을 효율적으로 관리하기 위한 기능:

- **검색**: 애플리케이션 이름으로 필터링
- **상태 필터**: 실행 중/중지된 애플리케이션만 표시
- **서버 필터**: 특정 서버/클러스터의 애플리케이션만 표시
- **정렬**: 이름, 상태, 시작 시간 기준 정렬

## 시작 기능

애플리케이션을 시작하는 절차는 다음과 같습니다:

### 시작 작업 수행

**단계:**

1. **애플리케이션 선택**
   - 목록에서 시작할 애플리케이션의 체크박스 선택
   - 여러 애플리케이션 동시 선택 가능

2. **시작 버튼 클릭**
   - 화면 상단의 "시작" 버튼 클릭
   - 확인 대화상자 표시

3. **시작 옵션 선택** (선택사항)
   - **일반 시작**: 정상 모드로 시작
   - **디버그 모드**: 디버거 연결 가능하도록 시작
   - **타임아웃 설정**: 시작 완료 대기 시간 (기본 60초)

4. **확인 및 실행**
   - "확인" 버튼 클릭하여 시작 수행
   - 진행 상태 실시간 표시

### 시작 결과 확인



**성공 시:**
- 상태 아이콘이 녹색으로 변경
- "실행 중" 상태 표시
- 시작 시간 기록
- 접근 URL 활성화

**실패 시:**
- 빨간색 오류 아이콘 표시
- 오류 메시지 및 원인 표시
- 서버 로그 링크 제공
- 재시도 옵션 제공

### 주의사항

**시작 전 확인사항:**
- 서버가 실행 중인지 확인
- 필요한 리소스(데이터소스 등)가 준비되었는지 확인
- 포트 충돌이 없는지 확인

**시작이 오래 걸리는 경우:**
- 대용량 애플리케이션 (100MB 이상)
- 많은 리소스 초기화 작업
- 데이터베이스 연결 풀 생성
- 타임아웃 설정 조정 필요

## 중지 기능

실행 중인 애플리케이션을 중지하는 절차입니다:

### 중지 작업 수행



**단계:**

1. **실행 중인 애플리케이션 선택**
   - 녹색 상태 아이콘이 표시된 애플리케이션 선택
   - 여러 애플리케이션 동시 선택 가능

2. **중지 버튼 클릭**
   - 화면 상단의 "중지" 버튼 클릭
   - 확인 대화상자 표시

3. **중지 옵션 선택** (선택사항)
   - **정상 중지**: 현재 처리 중인 요청 완료 후 중지 (권장)
   - **즉시 중지**: 모든 요청 강제 종료 후 중지
   - **타임아웃 설정**: 정상 중지 대기 시간 (기본 30초)

4. **확인 및 실행**
   - "확인" 버튼 클릭하여 중지 수행
   - 진행 상태 실시간 표시

### 중지 결과 확인

**성공 시:**
- 상태 아이콘이 회색으로 변경
- "중지됨" 상태 표시
- 실행 시간 기록 종료

**실패 시:**
- 오류 메시지 표시
- 강제 중지 옵션 제공
- 서버 로그 링크 제공

### 주의사항

**정상 중지 권장:**
- 활성 세션이 있는 경우 세션 데이터 손실 방지
- 데이터베이스 연결 정상 종료
- 리소스 정리 작업 완료

**즉시 중지 사용 시:**
- 애플리케이션 응답 없음 상태일 때만 사용
- 데이터 손실 가능성 있음
- 롤백이 필요한 트랜잭션 손실 위험

## 설치제거 기능

배포된 애플리케이션을 서버에서 완전히 제거하는 기능입니다.

### 설치제거 작업 수행



**단계:**

1. **애플리케이션 선택**
   - 제거할 애플리케이션 선택
   - 실행 중인 애플리케이션은 먼저 중지 필요

2. **설치제거 버튼 클릭**
   - "설치제거" 버튼 클릭
   - 경고 대화상자 표시

3. **확인 대화상자**
   ```
   선택한 애플리케이션을 완전히 제거하시겠습니까?
   
   - 애플리케이션: MyApplication
   - 배포 대상: Server1, Server2
   
   이 작업은 되돌릴 수 없습니다.
   ```

4. **설치제거 옵션**
   - **파일 보관**: 서버에서 제거하지만 파일은 백업 위치에 보관
   - **완전 삭제**: 파일까지 완전히 삭제

5. **확인 및 실행**

### 설치제거 결과

**성공 시:**
- 애플리케이션이 목록에서 제거됨
- server.xml에서 설정 제거됨
- 백업 파일 생성 (옵션 선택 시)

**실패 시:**
- 오류 메시지 표시
- 부분 제거 상태 확인
- 수동 정리 가이드 제공

### 주의사항

**설치제거 전 확인:**
- 애플리케이션이 중지된 상태인지 확인
- 다른 애플리케이션과의 의존성 확인
- 데이터베이스 데이터 백업 (필요 시)

**복구 불가:**
- 설치제거는 되돌릴 수 없음
- 재설치 시 새로 배포 필요
- 백업 옵션 사용 권장

## 업데이트 기능

기존 애플리케이션을 새 버전으로 교체하는 기능입니다.

### 업데이트 작업 수행



**단계:**

1. **애플리케이션 선택**
   - 업데이트할 애플리케이션 선택

2. **업데이트 버튼 클릭**
   - "업데이트" 버튼 클릭
   - 파일 업로드 화면 표시

3. **새 파일 업로드**
   - 새 버전의 WAR/EAR 파일 선택
   - 파일명이 동일할 필요 없음

4. **업데이트 옵션 선택**
   ```
   ○ 무중단 업데이트 (Rolling Update)
      - 클러스터의 각 서버를 순차적으로 업데이트
      - 서비스 중단 없음
      - 시간이 더 소요됨
   
   ○ 일괄 업데이트
      - 모든 서버를 동시에 업데이트
      - 빠른 업데이트
      - 짧은 서비스 중단 발생
   ```

5. **설정 변경** (선택)
   - Context Root 변경
   - 기타 설정 수정

6. **업데이트 실행**

### 무중단 업데이트 (Rolling Update)



클러스터 환경에서 서비스 중단 없이 업데이트하는 방법:

**진행 과정:**

1. **1단계: 첫 번째 서버 업데이트**
   - Server1 중지
   - 새 버전 배포
   - Server1 시작 및 헬스 체크

2. **2단계: 두 번째 서버 업데이트**
   - Server2 중지
   - 새 버전 배포
   - Server2 시작 및 헬스 체크

3. **3단계: 완료**
   - 모든 서버 업데이트 완료
   - 전체 클러스터 헬스 체크

**장점:**
- 서비스 중단 없음
- 사용자 영향 최소화
- 문제 발생 시 쉬운 롤백

**단점:**
- 업데이트 시간 증가
- 버전 호환성 고려 필요
- 클러스터 환경 필수

### 일괄 업데이트

모든 서버를 동시에 업데이트:

**진행 과정:**

1. **모든 서버 중지**
2. **새 버전 배포**
3. **모든 서버 시작**

**장점:**
- 빠른 업데이트
- 단순한 프로세스

**단점:**
- 서비스 중단 발생
- 동시 다운타임

### 업데이트 검증



**자동 검증 항목:**
- 애플리케이션 시작 성공 여부
- 헬스 체크 URL 응답 확인
- 주요 기능 정상 작동 확인

**수동 검증 권장:**
- 주요 비즈니스 기능 테스트
- 데이터 정합성 확인
- 성능 모니터링

### 롤백

업데이트 실패 또는 문제 발생 시 이전 버전으로 복구:



**자동 롤백:**
- 업데이트 실패 시 자동으로 이전 버전 복구
- 백업된 파일 사용
- 설정 복원

**수동 롤백:**
- 업데이트 이력에서 "롤백" 버튼 클릭
- 이전 버전 선택
- 확인 후 복구 실행

## Liberty와 LibriX 비교

| 항목 | Open Liberty | LibriX |
|------|-------------|--------|
| 애플리케이션 목록 | 명령줄 또는 파일 시스템 확인 | GUI 기반 통합 목록 |
| 개별 시작/중지 | 불가능 (서버 단위) | 가능 (애플리케이션 단위) |
| 업데이트 방식 | 파일 교체 + 서버 재시작 | 무중단 업데이트 지원 |
| 다중 서버 관리 | 각 서버 개별 작업 | 중앙에서 일괄 관리 |
| 상태 모니터링 | 수동 확인 | 실시간 자동 모니터링 |
| 롤백 | 수동 복구 | 자동/수동 롤백 기능 |

## 문제 해결

### 시작 실패

**증상:** 애플리케이션이 시작되지 않음

**원인 및 해결:**

1. **의존 리소스 없음**
   - 데이터소스, JMS 등 필수 리소스 확인
   - 리소스 생성 또는 설정 수정

2. **포트 충돌**
   - Context Root 중복 확인
   - 다른 애플리케이션과 경로 충돌 확인

3. **클래스로더 충돌**
   - Parent Last 설정 시도
   - 공유 라이브러리 버전 확인

4. **메모리 부족**
   - 서버 힙 메모리 확인
   - JVM 옵션 조정

### 업데이트 실패

**증상:** 새 버전 배포 중 오류 발생

**원인 및 해결:**

1. **호환성 문제**
   - Liberty 버전 호환성 확인
   - Java 버전 확인

2. **설정 변경 필요**
   - 새 버전의 요구사항 확인
   - 리소스 설정 업데이트

3. **롤백 수행**
   - 자동 롤백 대기 또는
   - 수동 롤백 실행

### 성능 저하

**증상:** 응답 시간 증가, 처리량 감소

**원인 및 해결:**

1. **메모리 누수**
   - 힙 덤프 분석
   - 세션 타임아웃 설정 확인

2. **데이터베이스 연결 부족**
   - 연결 풀 크기 증가
   - 연결 누수 확인

3. **스레드 부족**
   - 스레드 풀 크기 조정
   - 비동기 처리 고려
