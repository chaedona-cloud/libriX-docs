# 애플리케이션 설치

## 개요

애플리케이션 설치 메뉴는 LibriX 관리콘솔에서 엔터프라이즈 애플리케이션(WAR, EAR 파일)을 Open Liberty 서버에 배포하는 기능을 제공합니다. LibriX는 복잡한 배포 과정을 웹 UI를 간소화하여, 파일 업로드와 몇 가지 설정만으로 애플리케이션을 배포할 수 있습니다.

## 지원되는 애플리케이션 유형

LibriX는 다음과 같은 엔터프라이즈 애플리케이션 형식을 지원합니다:

### WAR (Web Application Archive)

Java 웹 애플리케이션을 패키징한 파일로, 다음을 포함합니다:
- Servlet, JSP 파일
- HTML, CSS, JavaScript 등 정적 리소스
- WEB-INF/web.xml (배포 기술자)
- WEB-INF/lib (라이브러리 JAR 파일)
- WEB-INF/classes (컴파일된 클래스 파일)

### EAR (Enterprise Application Archive)

여러 모듈을 포함하는 엔터프라이즈 애플리케이션으로, 다음을 포함할 수 있습니다:
- WAR 파일 (웹 모듈)
- JAR 파일 (EJB 모듈)
- RAR 파일 (리소스 어댑터)
- META-INF/application.xml (애플리케이션 기술자)
- 공유 라이브러리

## Liberty의 전통적인 애플리케이션 배포 방식

Open Liberty에서 애플리케이션을 배포하는 전통적인 방법:

### 1. Dropins 디렉토리 사용

가장 간단한 방법으로, 애플리케이션 파일을 dropins 디렉토리에 복사하면 자동 배포됩니다:

```bash
# WAR 파일 복사
cp myapp.war $WLP_HOME/usr/servers/myServer/dropins/

# 자동으로 배포됨 (server.xml 수정 불필요)
```

**장점:**
- 매우 간단하고 빠름
- server.xml 수정 불필요
- 자동 모니터링 및 재배포

**단점:**
- 고급 구성 옵션 제한
- Context Root, 클래스로더 등 커스터마이징 어려움
- 복잡한 엔터프라이즈 환경에 부적합
- 배포 대상 서버 제어 불가

### 2. server.xml에 직접 정의

보다 세밀한 제어가 필요한 경우 server.xml에 애플리케이션을 명시적으로 정의:

```xml
<server>
    <!-- 애플리케이션 정의 -->
    <webApplication id="myapp" 
                    location="myapp.war" 
                    contextRoot="/myapp"
                    name="MyApplication">
        <classloader delegation="parentLast"/>
        <application-bnd>
            <security-role name="Admin">
                <user name="admin"/>
            </security-role>
        </application-bnd>
    </webApplication>
</server>
```

**장점:**
- 상세한 설정 가능
- Context Root, 클래스로더, 보안 역할 매핑 등 제어
- 서버 재시작 시 동일한 구성 유지

**단점:**
- **XML 구문 복잡**: 모든 설정을 XML로 작성해야 함
- **수동 편집 필요**: 텍스트 에디터로 직접 수정
- **오류 발생 가능**: 구문 오류 시 서버 시작 실패
- **여러 서버 관리 어려움**: 각 서버마다 개별 설정 필요
- **중앙 관리 불가**: 분산 환경에서 일괄 배포 어려움

## LibriX의 애플리케이션 배포 방식

LibriX는 GUI 기반의 직관적인 배포 인터페이스를 제공하여, Liberty의 복잡한 설정 과정을 간소화합니다.

### LibriX의 주요 특징

**GUI 기반 배포**
- 복잡한 XML 편집 불필요
- 웹 UI를 통한 파일 업로드
- 드래그 앤 드롭 지원
- 실시간 유효성 검사

**중앙 집중식 관리**
- 여러 서버에 일괄 배포 가능
- 클러스터 단위 배포 지원
- WebSphere ND 스타일의 배포 대상 선택
- 통합된 배포 이력 관리

**자동 구성 생성**
- server.xml 자동 업데이트
- 애플리케이션 바인딩 자동 생성
- 클래스로더 설정 자동 적용
- 설정 오류 최소화

**배포 검증**
- 업로드 전 파일 유효성 검사
- 배포 전 서버 상태 확인
- 배포 후 자동 상태 모니터링
- 실패 시 자동 롤백 옵션

## 애플리케이션 설치 화면

애플리케이션을 설치하려면 LibriX 관리콘솔에 접속하여 다음 경로로 이동합니다:

```
설치 → 시작 → 실행 중 → 중지 → 업데이트/설치제거
           ↓
    [새 애플리케이션 설치]
```

### 설치 화면 구성

애플리케이션 설치 화면은 다음 단계로 구성됩니다:

#### 1단계: 애플리케이션 파일 선택

![애플리케이션 파일 선택](images/app_install/app_install_step1.png)

**파일 업로드 방법:**
- **찾아보기 버튼**: 로컬 파일 시스템에서 WAR/EAR 파일 선택
- **드래그 앤 드롭**: 파일을 드래그하여 업로드 영역에 놓기

**지원 파일 형식:**
- `.war` - 웹 애플리케이션 아카이브
- `.ear` - 엔터프라이즈 애플리케이션 아카이브

**파일 크기 제한:**
- 최대 파일 크기: 500MB
- 대용량 파일의 경우 진행률 표시

**유효성 검사:**
- 파일 형식 검증 (WAR/EAR 구조)
- 배포 기술자 (web.xml, application.xml) 검증
- 필수 리소스 존재 여부 확인

#### 2단계: 애플리케이션 설정

![애플리케이션 기본 설정](images/app_install/app_install_step2.png)

**애플리케이션 이름**
- 자동 생성: 파일명에서 확장자를 제외한 이름
- 수동 입력: 원하는 이름으로 변경 가능
- 제약 사항: 영문, 숫자, 하이픈(-), 언더스코어(_)만 사용 가능

**Context Root**
- 애플리케이션 접근 URL 경로 설정
- 예: `/myapp` → `http://server:port/myapp`
- 기본값: 애플리케이션 이름과 동일
- 슬래시(/)로 시작해야 함

**시작 순서**
- 여러 애플리케이션의 시작 순서 지정
- 낮은 숫자가 먼저 시작됨
- 기본값: 100
- 의존성이 있는 애플리케이션 관리에 유용

**자동 시작**
- 서버 시작 시 애플리케이션 자동 시작 여부
- 체크: 서버와 함께 자동 시작
- 해제: 수동으로 시작해야 함

#### 3단계: 배포 대상 선택

![배포 대상 선택](images/app_install/app_install_step3.png)

LibriX는 WebSphere Application Server ND 스타일의 배포 대상 선택을 제공합니다:

**서버 선택**
- 개별 서버 선택 가능
- 여러 서버 동시 선택 지원
- 서버 상태 실시간 표시 (실행 중/중지)

**클러스터 선택**
- 클러스터 단위 일괄 배포
- 클러스터 내 모든 멤버에 자동 배포
- 롤링 업데이트 지원

**배포 대상 정보 표시:**
- 서버/클러스터 이름
- 호스트 정보
- 현재 상태
- Liberty 버전

**배포 검증:**
- 대상 서버의 리소스 가용성 확인
- 포트 충돌 검사
- 필수 기능(Feature) 설치 여부 확인

#### 4단계: 고급 설정 (선택사항)

![고급 설정](images/app_install/app_install_step4.png)

**클래스로더 설정**
- **Parent First** (기본값): 부모 클래스로더 우선
- **Parent Last**: 애플리케이션 클래스로더 우선 (충돌 해결)

**공유 라이브러리 참조**
- 사전 정의된 공유 라이브러리 선택
- 여러 애플리케이션에서 공통 라이브러리 사용

**가상 호스트 매핑**
- 특정 가상 호스트에 애플리케이션 매핑
- 멀티 도메인 환경에서 유용

**보안 역할 매핑**
- 애플리케이션의 보안 역할을 실제 사용자/그룹에 매핑
- JAAS 인증 통합

**세션 관리 설정**
- 세션 타임아웃 설정
- 세션 복제 활성화
- 쿠키 설정 커스터마이징

#### 5단계: 설치 확인

![설치 확인](images/app_install/app_install_step5.png)

**설치 요약 정보:**
- 애플리케이션 이름 및 파일 정보
- Context Root
- 배포 대상 목록
- 선택한 고급 설정

**설치 옵션:**
- **즉시 시작**: 설치 완료 후 애플리케이션 자동 시작
- **나중에 시작**: 설치만 하고 수동으로 시작

**설치 진행:**
1. 파일 업로드 및 검증
2. 서버별 배포 진행
3. server.xml 자동 업데이트
4. 애플리케이션 시작 (선택 시)
5. 배포 결과 표시

## 배포 후 확인

### 설치 결과 확인

설치가 완료되면 결과 화면이 표시됩니다.

**성공 시:**
- 녹색 체크 아이콘 표시
- 배포된 서버 목록
- 애플리케이션 접근 URL
- 상태: "실행 중" 또는 "중지됨"

**실패 시:**
- 빨간색 X 아이콘 표시
- 오류 메시지 및 원인
- 롤백 수행 여부
- 재시도 옵션 제공

### 애플리케이션 상태 모니터링

배포된 애플리케이션은 **엔터프라이즈 애플리케이션** 메뉴에서 관리할 수 있습니다:

```
애플리케이션 → 엔터프라이즈 애플리케이션
```

배포된 애플리케이션은 엔터프라이즈 애플리케이션 메뉴에서 확인할 수 있습니다.

**표시 정보:**
- 애플리케이션 이름
- Context Root
- 배포된 서버/클러스터
- 현재 상태 (실행 중/중지)
- 시작 시간
- 요청 수 및 응답 시간 (선택적)

## Liberty와 LibriX의 비교

| 항목 | Open Liberty (전통 방식) | LibriX |
|------|------------------------|--------|
| 배포 방법 | Dropins 또는 XML 편집 | GUI 기반 웹 인터페이스 |
| 설정 복잡도 | 높음 (XML 구문 필요) | 낮음 (폼 기반 입력) |
| 다중 서버 배포 | 각 서버 개별 작업 | 중앙에서 일괄 배포 |
| 배포 검증 | 수동 확인 | 자동 검증 및 상태 모니터링 |
| 롤백 | 수동 복구 | 자동 롤백 옵션 |
| 배포 이력 | 없음 | 통합 이력 관리 |

## 주의사항

### 배포 전 확인사항

**서버 상태**
- 대상 서버가 실행 중이어야 함
- 서버 리소스(메모리, 디스크) 충분 확인

**포트 충돌**
- 다른 애플리케이션과 Context Root 중복 방지
- 가상 호스트 설정 확인

**의존성**
- 필요한 공유 라이브러리 사전 설치
- 데이터소스, JMS 등 리소스 설정 완료
- 필수 Liberty 기능(Feature) 설치 확인

### 문제 해결

**업로드 실패**
- 파일 크기 제한 확인 (500MB)
- 파일 형식 검증 (유효한 WAR/EAR)
- 네트워크 연결 상태 확인

**배포 실패**
- 서버 로그 확인 (`logs/messages.log`)
- server.xml 구문 오류 확인
- 리소스 부족 여부 확인

**시작 실패**
- 애플리케이션 의존성 확인
- 데이터소스 연결 테스트
- 클래스로더 충돌 확인
- Liberty Feature 설치 확인
